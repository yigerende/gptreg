# 风控监控

入口：运营控制台 → 风控监控（`/admin/risk`）。仅管理员会话可访问页面、后台静态资源与 `/api/admin/v1/risk/*` 接口；普通客户与开放 API 不获得风控配置。此功能参考回序的监控、客户规则和事件处置结构，适配注册订单和积分交付。

## 监控与处置

- 风险事件：登录验证失败、权限拒绝、接口服务异常、限流观察/拦截、兑换失败、订单幂等冲突和取消、管理写入操作。重复请求按身份、来源、类型和分钟合并，保留次数和响应状态。可标记已处理。
- 当前限制：查看规则、账号/密钥、次数及恢复时间，可手动解除；显示最近 100 条，指标显示全部匹配数。
- 客户规则：搜索客户，覆盖各业务次数，或暂停该客户新订单，支持指定恢复时间。未填写的次数继承全局，处理方式、窗口与冷却时间仍跟随全局。不会中断已受理任务、改变积分，也不阻止原幂等键确认已有订单。其他频率规则继续适用。
- 访问统计：按网页/API、客户、密钥和业务聚合请求、错误、拦截及平均耗时，可撤销密钥。显示访问量前 100 项，统计卡显示全量合计。风控页自身 GET 查询不计入。

日期按北京时间筛选事件及访问量；当前限制和客户规则是当前状态，只应用搜索条件，不应用历史日期。事件类别和处理状态仅过滤事件及相关指标。自动更新默认关闭；手动开启后仅在当前监控页面可见时更新，不刷新整页，进入配置页或离开后停止。

## 规则默认值

| 规则 | 模式 | 次数 | 窗口 / 冷却（秒） |
| --- | --- | --- | --- |
| 登录尝试 | 执行限制 | 10 | 900 / 900 |
| 兑换积分 | 执行限制 | 10 | 60 / 60 |
| 提交注册订单 | 仅观察 | 20 | 60 / 60 |
| 查询与轮询 | 仅观察 | 300 | 60 / 60 |
| 查看凭据与导出 | 仅观察 | 30 | 60 / 60 |
| 其他业务操作 | 仅观察 | 60 | 60 / 60 |
| 客户总请求量 | 仅观察 | 600 | 60 / 60 |
| 单个 API 密钥 | 仅观察 | 120 | 60 / 60 |

次数按请求数计算，和全平台/单用户“注册执行并发”是独立配置。登录以规范化账号标识计数；其他客户规则合并网页/API与多个订单。每个密钥另有自己的桶。PostgreSQL 原子计数支持并发和多应用副本，重启不会重置。达到次数后再来的请求触发超限，执行模式返回 429 和 Retry-After。限制到期重置窗口，不因重试延长封禁。

旧固定 API 总频率、下单频率和兑换频率由新规则接管，避免后台配置与隐藏硬限制冲突；注册、邮件验证码、重置密码的原保护保留。关闭“记录与异常检查”只停止记录/观察，不停止执行限制。管理员鉴权成功后可持续访问后台恢复配置。修改某条频率规则才重置其计数/限制，单纯修改刷新间隔不释放限制。配置版本冲突返回 409，需重新加载。

## 异常检查

应用每 5 秒检查一次是否到期，实际扫描默认每 60 秒，也可点击立即检查。使用数据库互斥锁，多个应用副本不会重复扫描；不需要注册引擎或执行 worker。扫描只读取业务状态：

- 已核实同一来源短时间登录多个账号、频繁幂等冲突或取消订单。
- 注册/授权最终失败比例、排队账号过多、排队超时、执行超时、结果待人工核实。
- 大额积分调整、账户冻结金额与未结算订单不一致、积分/冻结与账本累计不一致、订单交付/扣费/释放记录不一致。

业务异常只告警，不自动取消、重试、冻结客户或修正积分。持续异常被标记处理后保持已处理；问题消失后再次发生会产生新事件。记录只包含固定事件说明、业务 ID、客户身份、密钥名称和来源 IP，不保存请求正文、查询参数、原始错误、密码、兑换码、2FA、Cookie 或完整 API Key。

默认保存 30 天，清理仅针对独立 `platform_risk_*` 记录。业务订单、账本、交付资料不由风控清理；客户交付资料保留期限仍由账号模块管理。扫描和日志失败仅记录通用诊断，不输出敏感上下文。财务告警可能反映历史手工改库的初始余额，需人工核对账本，不能直接自动修正。

## 来源识别

默认不信任任何转发头，显示“来源未核实”。可信代理设置只填写站点前方已确认的反向代理 IP 或网段（最多 64 项，禁止 `/0`）；从真实 TCP 对端向前逐跳验证 X-Forwarded-For，取第一个非可信跳。单独伪造 X-Real-IP、CF-Connecting-IP 不建立可信来源。未核实来源不用于跨账号来源告警，来源 IP 不参与自动客户封禁，避免共用出口误伤。这与注册代理池无关。

## 数据与验证

数据库启动时执行独立、幂等的 `risk-schema.sql` 兼容迁移，保留既有主密钥与业务数据。配置、客户控制、限流桶和事件均持久化。本地实现完成后，用户授权与全部未提交代码一并推送和正式发布；正式版本以发布记录为准。

专项：`node --test test/platform-risk.test.js`（独立随机 schema），前端：`npm --prefix web test -- src/portal/AdminRisk.test.tsx`。不使用真实供应商、不启动付费注册任务。
