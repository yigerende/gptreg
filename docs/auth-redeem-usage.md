# 认证与兑换码使用统计（2026-11-05）

登录签发会话时持锁复核密码版本、邮箱和账户状态；注册和首会话同事务。个人改密持锁复核原凭据及会话，不能覆盖并发完成的重置。

邮件验证码按随机挑战 ID 和主密钥 HMAC 存储，不保存明文，发信成功才可消费。重置码绑定当时用户与密码版本；旧码不能在改密后使用。升级前无绑定的验证码失效，用户重新获取即可。注册发码检查注册开关、验证开关、域名白名单和已有用户；IP每日100、收件人每日20上限，并沿用每分钟和60秒冷却。

登录/注册/验证码来源统一使用后台风控的 trusted_proxies 配置；应用不直接信任任意转发头。生产应加入核实的直接代理地址及上游代理段。PUBLIC_ORIGIN 为本站实际来源（例如 HTTPS 域名），COOKIE_SECURE 可强制安全 Cookie；默认按真实 TLS、匹配的 HTTPS 来源或可信反代的 X-Forwarded-Proto 决定。

兑换码管理新增“使用情况”，支持北京时间日/周/月/年、统计日期、上一期/本期/下一期、字面搜索和服务端分页。周一为周起点；按实际 redeemed_at 统计次数、不同码、使用人数与入账积分，查询为只读一致快照，管理员权限及完整码隔离保持。

工作台与运营概览显示“敏感数据已加密保护”。原API key策略与业务执行流程保持。

验证包括61项平台测试、64项快速测试、174项前端测试（负载超时项单独复测通过）、构建与桌面/390px浏览器交互。Node 25本地测试需 NODE_OPTIONS=--no-experimental-webstorage 以使用jsdom存储；多项目共用测试PostgreSQL时使用 --test-concurrency=2，避免测试连接池耗尽。测试使用一次性schema和模拟SMTP，不发真实邮件或执行付费注册。
