# 自动恢复与结算

用户子项在首次领取时记录总执行起点，后续重试与 OAuth 不重置期限；普通排队不计执行时长。原任务恢复次数持久保存，并受订单创建时的次数限制约束。已创建或创建结果不确定的账号只恢复原任务，OAuth 只处理原资产。

`review` 是兼容历史状态，用户继续查询原订单即可。执行器自动恢复暂时等待、修复退款状态，并在超过执行期限或恢复预算后自动结束未交付部分、退回积分。账本是结算依据，已交付／已退款均不可回到处理中。管理员重复操作返回真实结算结果，不会二次退款或重新扣费。

完整账号资产可在引擎停止、仅资源收尾未完成时交付。退款或交付后的资源清理保存在 `platform_run_cleanup`，独立退避重试，不占用客户冻结积分；仍在执行的引擎保留真实执行槽及资源锁。退款后的迟到资产记录在 `platform_quarantined_assets`，不能再次交付。原注册台可查看账号资料，运营订单详情显示清理和隔离提示。

客户 API 新增可选字段 `recovery_attempts`、`next_retry_at`、`execution_started_at`、`execution_deadline_at`。查询建议每 5 秒一次，结束后停止；恢复中的订单不要重新下单。OpenAPI 1.4.0 仍保留原九个公开操作。

SMSBower 默认查询预算从 3 次调整为 24 次，任务计划不再固定覆盖为 3 次；120 秒等待上限仍生效。代理早期故障切换时重建该次失效会话，不移除身份连续性校验，不重建已确认创建的账号。

# 财务报表

按北京时间日、周、月、年分组，支持起止日期、账户搜索、包含管理员开关（默认关闭）。充值统计兑换入账，消费只统计成功交付扣费，订单预留／未交付退回不重复计入消费。当前可用积分直接读取 points，不再减 frozen，也不除以 100。

汇总、趋势、客户明细、流水和导出使用相同账户与日期口径及只读可重复读快照。当前余额是实时快照。邮箱／短信成本按执行开始时间统计，包括失败和重试，保留币种、待核对及缺失标记，不能直接与积分相减为利润。管理员 CSV 导出包含完整筛选下的客户，最多 10000 位，UTF-8 BOM 并防公式注入。
