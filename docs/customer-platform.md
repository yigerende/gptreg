# 用户平台与开放 API

React 19 / Fastify 5 保留。PostgreSQL 存储用户、积分账本、订单子项、交付归属和 API Key；原引擎运行文件只用于执行检查点。app 提供公开前台、受保护的后台和 API；worker 独占注册引擎，PostgreSQL advisory lock 防止重复领取，内部接口使用独立密钥，不发布端口。

## 用户流程

- 邮箱注册、密码登录、邮件验证码、找回密码、退出、修改资料。注册开关、邮件验证和域名限制均在后台设置。SMTP 未配置时不显示找回密码，不能开启强制邮件验证。
- 初始积分为零；管理员加款或兑换码充值。默认标准账号 50 积分、含 OAuth 100 积分，后台可改。含 OAuth 是完整单价，不再另加标准价。
- 只提交 quantity 和 need_oauth；下单预留积分，锁定单价、模板、重试上限和时限。只有完整交付时结算，部分失败/取消释放对应预留积分。
- 标准交付要求邮箱、已配置密码与 2FA；OAuth 模式首次使用原管理台“注册后 OAuth”的同任务流程（register_session + postRegistrationOAuth=true），要求 access_token / refresh_token。注册已成功但授权未完成时，只给同一资产补 OAuth，不重新注册。旧的两阶段订单/检查点继续兼容。结果不明进入 review，不盲目重放。
- 当前一个全局主任务，每轮执行一个客户子项，按订单最近调度时间轮转。后台原任务与用户任务共享引擎容量；未来扩大并发必须先隔离资源及检查点，不能直接扩容 worker。
- 我的账号可复制密码/2FA/当前验证码，导出 TXT（邮箱----密码----2FA）或 JSON（包含所购买的 OAuth 数据）。交付账号唯一绑定用户、订单和子项，并标记原引擎资产为已售。历史账号仍为管理员资产，不自动归属客户。

客户队列通过原 RunManager.start 启动任务，使用 schemaVersion=2。新注册与 OAuth 计划缺少代理分配时，后端按页面同样规则优先选有容量的国家池，否则选择固定代理；明确指定的代理保持。旧 schema 1 与已有检查点保留原语义。短信、邮箱密钥仍由原引擎配置管理，不接受客户提交资源参数。

用户网页在发送下单请求前按登录用户保存待确认请求（仅幂等键、数量和 OAuth 选项）。断网、5xx、刷新或返回页面后复用原请求，结果未确认时锁定数量与模式；收到明确成功后才开始新单。首次明确拒绝的 4xx 可以重新编辑，已不确定的请求遇到登录失效等情况仍保留；浏览器无法持久保存时不发送请求。跨标签使用浏览器锁（支持时）串行确认。

启动失败在管理员执行记录保存固定错误码、分类与脱敏说明，不保存供应商原始错误或密钥。代理/任务占用和 OAuth 冷却等待不消耗执行重试次数，受首次调度起的等待期限约束；配置错误仍按既有重试预算结束并释放积分。正常执行继续使用各次任务超时。

交付写入数据库后同步原资产为 sold，并以 platform_accounts.engine_sold_at 记录确认。写入中断、资产暂不可读时，持久待同步标记由后续循环/重启补齐，既不重复扣费也不把未交付账号标为已售。数据库升级仅新增兼容列及索引，保留历史数据。

## 入口与接口

用户 `/`、`/register`、`/orders`、`/accounts`、`/wallet`、`/keys`、`/profile`；平台管理 `/admin`；原管理台 `/admin/engine`。

客户文档 `/docs`，OpenAPI 3.1 `/openapi.json`。外部 API `/open/v1` 只接受 Bearer API Key；网页 `/api/user/v1` 使用 HttpOnly / SameSite Strict 会话。`/api/admin/v1`、原 `/api/v1` 及管理员 JS 包要求管理员会话。所有网页写操作检查同源及自定义头，不启用跨域。

原注册管理台入口位于运营控制台顶部右上角，仅管理员显示，点击在新标签页/窗口打开。后台页面 `/admin` 及其子路径、独立脚本 `/admin-assets/*` 均由服务端验证管理员会话；普通用户不会加载管理组件，直接请求返回 403，未登录返回 401。资源路径编码不能绕过检查。地址本身不是密钥，权限以服务端会话为准。

创建订单：

```http
POST /open/v1/registration-orders
Authorization: Bearer YOUR_API_KEY
Idempotency-Key: unique-order-request-001
Content-Type: application/json

{"quantity":10,"need_oauth":true}
```

返回 202 和订单 ID。相同用户同键同请求返回原订单（200），请求不同则 409。查询详情后，通过 accounts 的 order_id 过滤获取已交付结果。访问频率由运营控制台风控配置按业务、客户和 API 密钥管理，网页与 API 共用客户额度；轮询建议每 5 秒。执行限流返回 429 与 Retry-After；客户暂停新订单返回 403，已受理订单的原幂等键确认仍可用（其他频率规则继续适用）。密钥仅首次完整显示，数据库存摘要，可撤销，按 orders:read / orders:write / accounts:read / credentials:read 授权。详见 [风控监控](risk-monitor.md)。

### 开发者文档

`/docs` 使用独立品牌顶栏与分组文档目录，登录用户、访客均可查看（受文档功能开关控制）。提供目录搜索、深链接、移动端目录、字段说明、cURL / Python / Node.js 全局语言切换、请求场景选择、响应状态选择、复制和 OpenAPI 3.1 下载。页面只展示示例，不发送下单或导出请求，也不定时轮询。

`src/platform/openapi.js` 是九个开放接口的说明、字段、权限、状态和示例的共同来源，`web/src/portal/apiDocs.ts` 负责展开引用与生成调用代码。只涵盖 `/open/v1`，不包含运营或原注册管理接口。增加接口或字段时同步更新此契约；`test/platform-openapi.test.js` 用独立测试 schema 验证真实响应与文档，纳入 `npm run test:platform`。前端 `apiDocs.test.ts` 检查字段展开和示例，并通过 Python 3 / Node 语法检查；不会执行示例网络请求。

文档明确区分订单 ID、子项 ID 和交付账号 ID，覆盖标准/OAuth 完整单价、可用余额与预留积分、创建 202 / 幂等重试 200、取消返回子项、订单/账号的组合筛选及分页总数、结果待核实、限频与退避处理。导出响应始终为 `{filename, content}`；应保存 `content` 正文，JSON 格式保留所购 OAuth 数据，TXT/CSV 仅含邮箱、密码、2FA，导出不含实时验证码。

## 品牌与页面更新

运营控制台 → 站点设置 → 品牌与服务，可设置站点名称、英文名称、品牌说明、客服链接、服务约定及图标。默认提供本站 SVG 图标；支持静态 PNG（16～1024 像素，≤256 KB）或 SVG（≤20 KB，限安全几何图形），可恢复默认。图标存储在独立数据库，公开接口仅返回带版本的图片地址，不返回原始图片数据。

登录页、品牌信息和空闲页面不做定时查询。未登录是正常状态，不会周期性卸载登录表单。只有未结束的订单列表/详情每 5 秒更新局部进度，结算后停止并更新积分；其他页面进入时加载，可手动刷新。原注册引擎的实时任务监控保持。

## 工作台与运营控制台

参考 xufu-python 的整屏品牌栏、分组侧栏、深蓝概览、薄荷绿操作、统计卡片和表格布局。登录页、客户首页与注册服务页展示实时注册、Google Gmail 邮箱、动态高权重家宽注册三项服务特色。前台 `/register` 支持两种 OAuth 模式、实时报价和交付清单；首页使用自己的订单、已交付数量、实际扣费及最近七天趋势。

运营菜单包括概览、订单监控、积分报表、账户管理、账号交付、积分兑换码、服务与定价、站点公告、操作审计、站点设置。订单、账号、客户、账本、兑换码和审计支持服务端搜索及分页；客户详情有业务记录和账本，可创建普通用户、停启账户及调整积分。兑换码支持批量启用、停用与删除未使用记录，已兑换记录保留。

站点设置与 xufu 对齐为五栏：

- 功能开关：工作台、注册服务、订单、账号、钱包、开发接入、文档。关闭后前台隐藏入口且 API 拒绝访问；不影响已受理订单，管理员仍可管理。
- 安全与认证：开放注册、邮箱验证码、注册邮箱域名白名单。
- 邮件设置：SMTP、连接加密、授权码保留、测试发送及最近 90 天发送记录。只记录结果和脱敏错误，不存验证码或邮件正文；服务器接受不等同于收件箱已收到。
- 自定义菜单：最多 30 项，支持排序、启停、普通用户/管理员/所有登录用户可见、静态 SVG 图标、新窗口或站内嵌入。管理员专属配置只由鉴权接口返回，公共接口与普通用户接口不包含它们。
- 品牌与服务：站名、英文名、说明、图标、客服链接、服务约定。

用户顶部公告中心支持未读标记与全部已读，阅读状态按用户保存在当前浏览器。个人设置展示账户信息、积分与业务概览，并以独立弹窗编辑资料和密码。公告支持多条内容、启停、排序和定时上下线；旧单条公告保持兼容。积分报表按北京时间统计实际账本扣费，不把预留重复视作收入。新邮件记录表由现有初始化流程创建；所有新增设置有兼容默认值，不覆盖正式旧配置。外部嵌入受目标站点策略限制，可使用新窗口模式。

本轮仅改新增平台，原注册管理台的业务页面保持独立。

## 订单、资金与个人设置

用户 `/orders` 为订单中心：完整订单号与复制、提交来源、注册/OAuth 模式、数量、交付进度、单价/扣费/退回/待结算、状态与更新时间，支持服务端搜索、模式/状态筛选和每页 20 条分页。详情与领取账号入口关联当前订单；只有存在未结束订单时局部更新。

`/wallet` 为资金账户：可用积分卡、预留积分、兑换入账及已配置客服入口，分别查看资金流水和充值记录。按类型、关键词和北京时间日期筛选；汇总覆盖全部匹配记录，不只当前页。账本可追溯关联订单。`points` 已是可用积分，不能再次减去 `frozen`；扣费从预留结算。新账本在同一事务保存 `points_after` / `frozen_after`，旧行保持空并显示“历史记录未保存余额快照”，不推算或补造历史金额。充值记录包括兑换及正向人工调账，不虚构尚不存在的充值申请流程。

`/profile` 为个人设置：身份卡、可用/预留积分、订单/完成/进行中/累计消费统计，以及可筛选的注册记录。编辑用户名和修改密码为独立弹窗，改密验证旧密码和两次新密码，成功撤销旧会话与 API Key。关闭订单或资金功能时，相应摘要和关联记录均由服务端裁剪。

运营后台 `/admin/accounts` 支持查看每个交付账号的邮箱、密码、2FA 密钥、当前验证码、全部 OAuth 字段与原始 JSON，以及所属客户、订单、资产、时间和售出同步状态；验证码按需刷新。单个或勾选批量下载：完整 JSON 包含原始交付凭据和 delivery 归属对象，CSV 包含凭据/OAuth/归属，TXT 为邮箱----密码----2FA。CSV 对公式前缀文本添加保护字符；需要逐字保留原始字段时使用 JSON/TXT。每批 1～1000 个，未知 ID 拒绝整批导出；按请求 ID 顺序去重。

管理读取 `/api/admin/v1/accounts/:id/credentials` 与导出 `/api/admin/v1/accounts/export` 仅管理员网页会话可访问，普通用户、匿名和 API Key 不能访问。返回 no-store，读取/导出记录操作者、账号 ID 与格式，不记录凭据。交付列表不包含秘密，只有显式查看/导出时解密；不改账号状态或客户积分。上述管理和站内资金接口不进入客户 `/open/v1` 文档，九个公开接口协议不变。

运营控制台顶部、手机侧栏和页底的用户工作台入口均新标签页打开，原运营页面保留。全站隐藏竖向滚动条且保留滚动能力；Chromium 保留横向表格滚动条，Firefox 水平表格使用独立细滚动条。

## 数据与恢复

所有金额为整数积分，事务、行锁、账本唯一 reference 共同保证只结算一次。取消与转入重试/授权阶段共用订单锁，防止取消后的积分永久挂起。每次执行先持久化唯一 run_id，再启动引擎；重启时读取原检查点，缺失或结果不明时转人工核实。

管理员订单详情可查看原任务、恢复原任务或确认未交付并退款。未知结果必须先核实，不能为了释放占位直接重复注册。关闭接单不会中断已受理订单，关闭领取会让已执行部分收尾。

交付凭据、SMTP 密码和引擎关键凭据使用 AES-256-GCM，主密钥位于 `.runtime/platform-secrets.json`。API Key 与会话仅保存摘要，用户密码用带随机盐的 scrypt。旧文件迁移工具支持加密与解密，须停执行器后操作。配置文件及历史运维备份仍需要以 0700 目录/0600 文件和受控备份存储保护；主密钥必须与数据库同时备份。

## 客户注册并发与排队

运营控制台「服务与定价」可分别配置全平台注册并发与单用户注册并发，默认均为 15，取值 1～100。单用户的所有网页/API订单合并计数，注册、注册并 OAuth、原账号补授权共用限额。订单中的每个账号独立领取执行名额；提交 100 个时先启动最多 15 个，后续排队，每结束一个自动补位。多个订单轮流调度，已达单用户上限的客户不会堵塞其他客户。

新安装默认每单上限 100；旧站点保留原上限，可在后台调整。降低并发不取消在途任务，待占用降到新上限后再领取；暂停或恢复任务仍计入容量，重启不重复注册或扣费。订单详情显示执行中与排队中数量。原注册台手动主任务和附属任务保留其容量，客户订单使用独立执行容量，共享代理独占与账号锁。供应商资源不足时可能达不到设置上限。

开放 API 的请求参数及九个接口不变；网页与 API 共用此队列。调用方只需提交数量和 OAuth 选项，不能指定或绕过并发额度。每单最大数量仍以 `/open/v1/products` 的 `max_quantity` 为准。

## 运营兑换码管理

参照 xufu 提供发行弹窗、发行统计、批次与有效期、未使用/已使用/停用/过期筛选、单条与批量复制、TXT 导出及批量启停/删除。生成结果可直接点击每条兑换码复制，也可复制全部或下载。仅有效未使用的兑换码能导出，已兑换记录不可删除；过期码不可充值。

新码用平台主密钥加密保存完整内容，列表和审计不返回原文，仅管理员复制/导出接口解密。历史码保留原有效性与兑换记录；原先只有哈希且未保存原文的码会标注「历史码 · 未保存原文」，无法恢复复制。兼容迁移新增 encrypted_code、batch、expires_at，不替换旧数据或主密钥。


## CPA / SUB 导出及大批量下载

用户「我的账号」和运营「账号交付」均支持 CPA、SUB，以及「邮箱-密码-2fa」。CPA 单个账号直接下载独立 Codex OAuth JSON；多个账号下载 ZIP，内部一号一份 JSON。SUB 复用原引擎转换器，将多个账号合并为 sub2api 的 exported_at / proxies / accounts 导入文件，账号 platform=openai、type=oauth，credentials 包含 token 及解析后的账号信息。已按本地 sub2api account_data.go 与 CLIProxyAPI auth_files_crud.go 导入结构核对，不启动或更改这两个项目。

仅完整 OAuth 交付可导出 CPA/SUB，混入标准账号整批拒绝。原始完整 JSON 和 CSV 接口保留。网页支持选择当前筛选结果最多 1000 个，选择期间显示读取数量，生成下载期间持续转圈显示账号数并阻止重复提交。

开放 API accounts/export 新增 cpa、sub 两个 format，单次上限从 100 扩为 1000。仍返回 filename / content；仅 CPA ZIP 额外返回 encoding=base64，调用方须解码为字节再写文件。其他格式 content 为 UTF-8 正文。OpenAPI 升至 1.2.0，Python/Node.js 示例包含 Base64 处理，原 txt/csv/json 调用保持兼容。


## 我的账号分组与领取期限

用户账号按订单展开或按账号平铺，支持整单、跨单、跨页选择，合计最多 1000 条；交付成功起算 72 小时后移除用户端可领取资料，运营后台完整保留。公开 API 同样执行到期限制，列表及凭据新增 `download_expires_at`，OpenAPI 1.3.0。详情及上线旧数据行为见 [account-retention.md](account-retention.md)。

## 运营资源、执行成本与交付分组

原启动工作台及运营概览展示邮箱库存、邮箱余额、邮箱单价、短信余额和短信最低单价；运营概览同时展示主任务、附属任务、客户任务的运行容量。资源接口 `/api/v1/resources/summary` 仅管理员可用，仅查询供应商，不租用邮箱或短信。余额与报价按配置缓存约 65 秒，任务容量即时读取，页面按需刷新。邮箱余额使用 SMSBower 邮箱配置的 API Key；短信最低价是当前供应商、服务及国家的最低报价，实际费用以账务记录为准。读取失败或供应商不支持时显示未知，不当成零余额。

运营概览、积分报表、订单监控/详情、账号交付/完整资料显示邮箱与短信执行成本。概览和报表按选定近 N 天（北京时间自然日）开始的执行尝试汇总，包含失败与重试，并非按供应商账单日期汇总。订单包含整单全部尝试，账号包含对应子项全部尝试；费用与用户积分分别核算，USD/CNY 等币种分列，待核对及已退款金额单独列示。仅包含引擎已有的供应商计费记录，不推算外部采购成本。

金额快照保存在 `platform_attempts.cost_snapshot`，不含密钥或凭据。活动执行约每 10 秒同步，结束再次同步；历史记录每 30 秒回填最多 20 条，未结算/缺失记录至少间隔 5 分钟重查。任务文件缺失时保留已有金额，无有效快照显示暂无记录，不能据此认定免费。兼容迁移只增加列和索引。

运营账号交付按订单折叠，展开才分页读取账号；整单、跨单和筛选结果选择最多 1000 条，保留查看、复制与所有导出格式。管理员完整 JSON/CSV 附带执行成本，CPA/SUB/TXT 导入格式不变。订单监控每行末尾提供独立「订单详情」按钮。以上成本和管理接口不对普通用户或公开 API 开放，公开 API 协议无需变更。
